# Бизнес-требования: youHoo

## 1. Назначение продукта

Приложение предназначено для личного общения между зарегистрированными пользователями. Основные сценарии: просмотр общего каталога контактов, обмен текстовыми сообщениями и изображениями, просмотр статусов пользователей и работа с перепиской без подключения к интернету.

## 2. Основные функциональные требования

### 2.1. Авторизация и профили

#### Авторизация

- В целевой версии вход выполняется через email и пароль либо одноразовый email-код (OTP).
- В текущем прототипе регистрация выполняется по display name и стабильному идентификатору установки; это не полноценная аутентификация.
- Зарегистрированный профиль сохраняется удалённо и появляется в общем каталоге.
- В целевой версии сессия авторизации сохраняется между запусками.

#### Профиль пользователя

- Пользователь может изменять отображаемое имя; изменение синхронизируется с удалённым профилем.
- В целевой версии пользователь может загружать и изменять аватар.

#### Контакты

- Список содержит всех зарегистрированных пользователей, кроме текущего пользователя.
- Пользователь может открыть личный диалог с любым контактом из списка.
- Предустановленный семейный список и ограничение круга контактов не используются.
- Поиск по идентификатору не требуется.
- В целевой версии контакты отображаются карточками с актуальными статусами.

#### Статус пользователя

- Пользователь может выбрать иконку-эмодзи статуса, например: 🏠 — дома; 🚗 — в пути; 💼 — на работе; 🔋 — сплю.
- Пользователь может добавить короткую текстовую подпись к статусу.
- Статус отображается в списке контактов и в шапке чата.

### 2.2. Личные чаты и сообщения

- Для пары пользователей существует один личный диалог, независимо от того, кто открыл его первым.
- Сообщение одного диалога не отображается в другом диалоге.
- История загружается страницами; более старые сообщения подгружаются по мере просмотра.

#### Статусы доставки

| Отображение | Значение |
|---|---|
| Одна галочка | Сообщение отправлено на сервер |
| Две серые галочки | Сообщение доставлено на устройство получателя |
| Две цветные галочки | Сообщение прочитано |

Статус «доставлено» устанавливается после получения сообщения устройством через Supabase Realtime или FCM. В прототипе receipt timestamps общие для пары; per-user watermarks являются целевой моделью для масштабирования на группы.

#### Непрочитанные сообщения

- При открытии чата экран автоматически прокручивается к первому непрочитанному сообщению.
- Над первым непрочитанным сообщением отображается разделитель «Непрочитанные сообщения».
- После пролистывания или закрытия чата соответствующие сообщения помечаются прочитанными.
- При следующем открытии разделитель для уже прочитанных сообщений не отображается.

#### Удаление сообщений

- **У себя:** сообщение скрывается только для текущего пользователя и остаётся доступному другому участнику.
- **У всех:** сообщение удаляется для всех участников переписки через soft-delete tombstone.
- Если удалённое сообщение содержало изображение, соответствующий файл также удаляется из облачного хранилища.

### 2.3. Офлайн-режим

- В целевой версии переписка хранится в локальной базе данных устройства.
- Экран чата получает данные из локальной базы, а не напрямую из сети.
- При появлении нового сообщения оно сохраняется локально, после чего экран обновляется.
- При отсутствии интернета чат открывается сразу и показывает сохранённую историю.

### 2.4. Быстрые реакции

- Пользователь может отправлять короткие реакции без ввода текста, например: ❤️, «Выезжаю», «Жду на ужин».
- Быстрый ответ можно отправить одним нажатием непосредственно из уведомления.

## 3. Будущие улучшения

### 3.1. Индикатор заряда батареи

- Приложение передаёт уровень заряда устройства с согласия пользователя.
- Уровень заряда отображается рядом с контактом.

### 3.2. Гео-отметки по запросу

- Постоянное отслеживание местоположения не используется.
- В чате доступна кнопка «Где ты?»; получателю приходит системное уведомление.
- Телефон получателя отправляет текущие координаты или название настроенной локации только после соответствующего разрешения.

### 3.3. Общие списки

- В приложении может появиться отдельная вкладка для общих списков покупок или дел.
- Участники общего списка могут добавлять и отмечать выполненными элементы в реальном времени.
